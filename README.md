# Прототип портала международных новостроек

Статичная вёрстка страниц на HTML и CSS, без сборки. Данные на страницах тестовые: избранное, сравнение и
фильтры каталога работают на них в браузере (`js/mock-data.js`), чтобы пустые и неполные состояния получались
действиями, а не отдельными страницами.
На следующем этапе разметка переносится в шаблоны Blade, классы и структура блоков сохраняются.

## Как открыть

Любой статичный сервер из корня папки, например:

```bash
python -m http.server 8766 --bind 127.0.0.1
```

Затем http://127.0.0.1:8766/html/index.html. Через `file://` страницы тоже открываются.

Опубликован через GitHub Pages из ветки `main`: https://torfinkissed1.github.io/ukris-prototype/ (корневой
`index.html` сразу переводит на `html/index.html`, `.nojekyll` отключает обработку файлов на стороне GitHub).
Каждый пуш в `main` обновляет сайт за минуту-две.

## Страницы

| Файл | Что показывает |
|---|---|
| `html/index.html` | Главная: первый экран с поиском, направления, проверенные проекты с «Показать ещё», вопросы о подходе, «Также рекомендуем к просмотру» с «Показать ещё», форма подбора. «Показать ещё» без скрипта ведёт на следующую страницу каталога, догрузку карточек добавим на этапе с сервером |

С фильтром в адресе (`catalog.html?country=turkey`, отправка формы фильтров, таблетки, сортировка) выдача, итог, заголовок и таблетки строятся по тестовым данным; если ничего не нашлось, «Объекты не найдены» с заявкой на подбор `#podbor-modal`. Пример пустой выдачи: семь фильтров «Таиланд, Пхукет, 50-100 тысяч $, виллы, сдан, «вид на море»», видно шесть таблеток, седьмая за «Ещё 1» |
| `html/object.html` | Карточка объекта: галерея, основные сведения и цена в валюте застройщика с пересчётом в доллары, описание, расположение, условия оплаты, планировки, инвестиционный комментарий, источники; окна «Запросить условия» (объект подставлен) и «Получить подборку» |
| `html/about.html` | О проекте: роль портала, как отбираются проекты, как работает заявка; блок контактов `#kontakty` с реквизитами |
| `html/privacy.html`, `html/consent.html`, `html/disclaimer.html` | Юридические документы на одном шаблоне `doc`: политика обработки данных, согласие, справочная оговорка. Тексты черновые, на странице есть пометка |
| `html/compare.html` | Сравнение трёх объектов одной панелью: сверху карточки (фото, «в избранное» и «убрать», цена, название, «Запросить условия»), ниже группы «Основное», «Оплата», «Комментарий эксперта», подпись строкой над значениями. На телефоне таблица листается вбок внутри панели, подписи стоят у левого края. Справа от заголовка «Очистить сравнение». Колонки строятся по списку сравнения: корзина убирает объект, «Очистить сравнение» ведёт к пустому состоянию «Добавьте объекты для сравнения» |
| `html/login.html` | Вход: почта с согласием и «Войти», внизу «Нет аккаунта? Зарегистрироваться». Принимает любую непустую почту и сразу ведёт в кабинет; шаг с кодом из письма появится на этапе с сервером. Панель в рамке по центру экрана, подвал ниже первого экрана |
| `html/register.html` | Регистрация: имя, телефон с маской, почта, согласие; после отправки сразу кабинет. Внизу «Уже есть аккаунт? Войти» |
| `html/cabinet.html` | Личный кабинет одной страницей с разделами-якорями: избранное `#izbrannoe` (карточки с «Убрать»), сравнение `#sravnenie`, мои заявки `#zayavki` (номер, объект или подбор, дата, статус), профиль `#profil` с окном подтверждения удаления аккаунта `#delete-account`. Избранное и сравнение строятся по сохранённым спискам, у пустого списка строка и кнопка в каталог |
| `html/404.html` | Страница не найдена, переход в каталог; закрыта от индексации |

Избранное и сравнение хранятся в браузере (`localStorage`, ключи `proto-favorites` и `proto-compare`). Пока их не
трогали, в каждом по три объекта, как в разметке; счётчики в шапке, нижней панели и меню кабинета считают списки.
В сравнении не больше четырёх объектов, пятый вытесняет самый ранний. Вернуть исходное состояние: очистить
данные сайта в браузере. Главная и каталог пока не ссылаются на карточку объекта.

Шапка, нижняя панель с листом меню и подвал на новых страницах скопированы из `catalog.html`; правятся
во всех страницах сразу.

Правила:
- классы по БЭМ (`block__element--modifier`), цвета и размеры только через переменные;
- раскладка на flex, grid только у сеток карточек и для наложения текста на фото;
- брейкпоинты 1240, 1024, 768, 480, 400; с 1024 px и уже включается мобильная схема;
- всё работает и без скриптов: листы и окно заявки открываются через `:target`
  (`#menu`, `#filters`, `#sort`, окна заявок `#podbor-modal` и `#usloviya`, закрытие ссылкой на `#`), выпадашки сделаны на
  `<details>` с радиокнопками, фильтры отправляются обычной GET-формой, сортировка и страницы это ссылки;
- анимации листов и выпадашек на CSS (`@starting-style`, `transition-behavior: allow-discrete`): где браузер
  их не умеет, окно просто открывается сразу; при `prefers-reduced-motion` переходы выключены;
- кольцо фокуса только с клавиатуры, у полей ввода фокус показывает цвет рамки;
- полосы прокрутки браузера скрыты везде (`base.css`), прокрутка работает колесом, жестом и клавишами;
- ховер-стили только внутри `@media (hover: hover)`: на тач-экране ховер остаётся после нажатия, и снятое
  сердечко выглядело бы отмеченным;
- всё открывается и закрывается плавно в обе стороны: выезд ключевой анимацией (на iPhone `@starting-style`
  у `<details>` и `overlay` у `<dialog>` не работают), уход классом `picker--closing` / `sheet--closing`,
  который ставит скрипт и ждёт конца анимации;
- перед коммитом, который уйдёт на GitHub Pages, запускать `python -X utf8 tools/cache-bust.py`: он ставит к
  подключениям стилей и скриптов метку `?v=` из хеша файла, иначе браузер берёт новую страницу со старым скриптом
  из кеша (Pages кеширует каждый файл на 10 минут отдельно);
- в окнах заявок кнопка отправки на всю ширину, согласие под ней (`modal__submit`, `modal__consent`);
- на телефоне (до 768 px) одиночная кнопка во всю ширину: под секциями, в пустых состояниях, в формах, на 404,
  «Удалить аккаунт», «Презентация проекта»; рядом по половине только пара кнопок в одном ряду. До 480 px у кнопок
  боковые отступы 16 px, чтобы подпись не переносилась;
- атрибут `hidden` прячет и блоки со своим `display` (`base.css`): им скрипты показывают и прячут пустые состояния.
- в формах заявок первое поле `company_website` это приманка для ботов, скрыта за экраном классом `trap`.

На компьютере шапка закрепляется только на главной, в каталоге за прокруткой едет панель фильтров.
На телефоне и планшете шапки нет: навигация в нижней панели, поиск и кнопка «Фильтры» в строке сверху.

Формы отправляются методом POST, статичный сервер на них отвечает ошибкой: переход с экрана почты на экран кода
и отправка заявок заработают на этапе с сервером. Экраны открываются и напрямую по адресу.

Пока не сделано, нужно на этапе с сервером: отправка кода и лимиты на неё (согласовать до реализации),
выход из кабинета формой POST (сейчас ссылка на `login.html`), серверная проверка форм (в том числе «такой почты
нет»), маска телефона в поле «Контакт», когда в нём цифры, сохранение избранного в аккаунте, список городов под выбранную страну, поиск по
строке «Проект, город или застройщик». В карточке объекта: просмотр фото галереи крупно, настоящие схемы
планировок (сейчас на их месте фото интерьеров) и файл презентации (ссылка пустая).

## Внешние зависимости

- Шрифт Montserrat (OFL) с Google Fonts. Если сервис недоступен, текст показывается системным шрифтом.
  Для боевого сайта шрифт лучше положить на свой сервер.
- Свайп листов свой (`js/swipe.js`, 70 строк на Pointer Events): готовые решения для листов снизу либо
  привязаны к React, либо приносят свою разметку листа и не работают с `<dialog>` и `<details>` прототипа.
- Иконки: пути из Tabler Icons 3.50.0 (MIT), вставлены спрайтом в начало каждой страницы. Иконка
  сравнения своя.
- Фото объектов и логотип взяты с сайта hotdeals.estate того же владельца. Фон первого экрана
  (`img/hero-dubai.webp`) сгенерирован нейросетью gpt-image-2.5.
